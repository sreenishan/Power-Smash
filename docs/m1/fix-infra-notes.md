## 2. What was done, with evidence

### S-2 (privacy scan evasion)
- **Reproduced.** The old `indian-mobile-number` regex was run on ten of the reviewer's inputs (`98765&nbsp;43210`, `98765.43210`, `(98765) 43210`, `9876<b>5</b>43210`, Tamil-digit number, `tel:%2B919876543210`, `9876 543 210`, `999-990-0000`, `98-76-54-32-10`, decimal-entity digits): all ten missed.
- **Fix.** New `scripts/lib/text-normalise.ts` (pure): decodes numeric entities (decimal, hex, with or without `;`) and the named entities that spell ASCII punctuation, spaces and dashes (table of about 70, no dependency and no full HTML5 table), percent-encoding of ASCII, JS and JSON escapes (`\uXXXX`, `\u{..}`, `\xXX`, `\/` `\.` `\@` ...), removes zero-width and bidi characters, folds full-width forms and no-break spaces (NFKC), maps every Unicode decimal digit (Tamil, Devanagari, Arabic-Indic, full-width, mathematical) to 0-9, strips markup (inline tags and comments join, other tags become a space, script and style content untouched). `scripts/privacy-scan.ts` reads every file three or four ways (`raw`, `decoded`, `plain` for HTML and SVG, `b64` for base64 blobs decoded, secrets only) and reports the same thing once: per rule, line and value the reading with the most hits wins, so a number written twice on a line is still two findings. `scripts/lib/privacy-rules.ts`: phone numbers in any grouping of 2-6 digits per group with `.` `-` space and brackets (generated from all compositions of ten digits, exact boundaries so `0.98765 43210`-style floats, hashes and timestamps are not taken), `+91`/`91`/`0` prefixes, Indian landlines (`044 2345 6789`), `[at]`/`(at)` and `[dot]` emails, bare 10-digit literals in scripts and SVG (`indian-mobile-number-code`), Turnstile secret shape, Resend shape (pure snake_case identifiers excluded), `"sb_"+"secret_..."` joins, base64-hidden secrets.
- **Allowlist is exact and tested.** `CODE_NUMBER_ALLOWLIST` (exact file plus exact digits) ships EMPTY because the real build output needs no exception; `isAllowedCodeNumber` and the scan honour a list passed in, tested for exactness (other file, other number, longer number, sub-path all refused).
- **False positives checked on real output.** The current `dist/client` still gives exactly the 93 `localhost-url` hits of a non-production build and nothing else (with the fake `PUBLIC_WHATSAPP_NUMBER` set, as before); four large third-party bundles (react-dom, react, astro-island, zod) give zero findings. A fixture of typical bundle content (timestamps, 2^31 and 2^53 constants, floats, hashes in `integrity` strings, `data-astro-cid-...`, the 16-digit Facebook page id inside a URL, prices, `7 8 9 10 11 12`) is a test and gives zero.
- **Known limits (heuristics, a miss proves nothing).** Words (`owner at gmail dot com`, digits spelled as words) are not matched; named entities outside the table are not decoded; base64 is decoded only for blobs of 24 or more characters; a number split by arbitrary text is not joined. The bare-number rule would also flag a 10-digit constant starting 6-9 in a script: that is what the allowlist is for.
- Files: `scripts/lib/text-normalise.ts` (new), `scripts/lib/privacy-rules.ts`, `scripts/privacy-scan.ts`. Tests: `tests/infra/privacy-evasion.test.ts` (new, 49 tests), `tests/infra/text-normalise.test.ts` (new), `tests/infra/privacy-scan.test.ts` (one expectation changed on purpose: a bare number in a script is now reported).

### S-8 (tracked-file refusal bypass)
- **Reproduced** with a real temp git repository and a real Windows junction: direct path refused, the same file through the junction returned `null` (allowed).
- **Fix.** `scripts/lib/secrets-file.mjs`: `realGit.tracked(dir, name)` and `realGit.ignored(dir, name)` run `git ls-files --error-unmatch` and `git check-ignore -q` with the file's own folder as working directory and the bare file name; git resolves junctions, symbolic links, `subst` drives, short (8.3) names and relative paths itself. They answer true, false or null (git could not answer); null refuses with a plain message (fail closed). Both the given path and its `realpath` are checked. `top(dir)` returns null only for "not a repository" or "git not installed". The injected-git interface of the old tests (`top`, `tracked`, `ignored` returning booleans) still works. `scripts/make-age-keys.mjs`: `insideProject` compares real paths through the nearest existing parent (exported with `realPathOfNearest` for tests); a folder named `..keys` is no longer mistaken for "outside".
- Tests: `tests/infra/secrets-paths.test.ts` (new, 13 tests, real git): direct, junction (tracked, plain, ignored, nested), relative path and `..` segments (child process with its own working directory), Windows 8.3 short name (this PC has 8.3 names on; the test skips itself when they are off), fake-git call shape, fail-closed, both-paths-checked, age key helper (junction, missing parents, sibling folder). The file-symbolic-link test skips itself on this PC (creating file symlinks gives EPERM without the privilege); the same logic is covered by the injected `realpath` test. `subst` drives were not tested.

### S-15 (/go click log)
`src/lib/infra/click-limit.ts` (new, pure): dedupe (same slug and user agent within 5 s is not written again; a refused duplicate does not extend the window) and a flood cap (120 rows per slug per 60 s whatever the user agents are), memory bounded (2,000 remembered pairs, oldest dropped, user agent cut to 256 characters, never stored). `handleGo` asks the limiter only for requests that would be counted (bots, prefetch and HEAD never reach it and never use up the cap); a limited request is still redirected, it just writes no row. `createGoDeps` installs one shared limiter per isolate. Tests: 500 identical requests give one row and 500 redirects; a loop that rotates user agents is capped and resumes in the next window; per-slug budgets; window boundaries; memory bound.
- **Limits, stated honestly:** per isolate, best effort, not a security boundary (several isolates multiply the cap; an attacker can still add up to the cap per minute per slug). Shared phone user agents make a long dedupe window undercount, hence 5 s. The stronger control is a Cloudflare rate-limiting rule on `/go/*` (owner task, dashboard) before any sponsor link goes live. The review's "Sec-Fetch-Mode: navigate" check was NOT adopted: curl can send that header, so it adds nothing.

## 3. Proposed decisions (for the lead to record)

**PD-A: Production builds are strict only (supersedes the infra PD-3 "two deploy modes").**
- Context: review C-5 and CLAUDE.md "Ask first": a page with a placeholder is a publication that needs the owner's yes. The old workflow ran the gates non-strict unless `PS_STRICT` was set or indexing was on, so a custom-domain deploy with the variable unset would have published red TODO badges.
- Decision: `.github/workflows/deploy.yml` runs only `npm run build:strict` with `PS_STRICT=1`, on `refs/heads/main` only. `npm run build` is the developer and CI build and says so.
- Consequences: no deploy until every `TODO(owner)` input is supplied or its section hidden (130 markers today). The owner's phone review before G1 needs an owner-approved alternative: a noindex preview that deliberately shows the placeholders (for example a separate workflow dispatched by hand, a repository variable the owner sets explicitly, workers.dev host only, never the custom domain). Owner approval needed.

**PD-B: The `/go` click log has a per-isolate brake.** Context: S-15. Decision: dedupe 5 s per slug and user agent, 120 rows per slug per minute, in memory; plus a Cloudflare rate-limiting rule on `/go/*` as an owner task before sponsor links exist. Consequences: counts are slightly conservative under heavy bursts; abuse is bounded but not impossible.

**PD-C: The privacy scan reads decoded text.** Context: D-029 says "decoded output". Decision: every dist file is scanned raw, decoded, tag-stripped and (secrets) base64-decoded; bare 10-digit numbers in scripts and SVG are reported; the only exceptions are the official contacts and an exact file-plus-number allowlist that ships empty. Consequences: a template that writes a contact detail in any of the usual disguises fails the strict build; an unusual false positive needs a one-line allowlist entry with a reason.

**PD-D: Owner-stated figures go stale after 90 days.** Context: C-17, D-016 item 5 (30 days for API data). Decision: `channel.asOfDate` (and `audience.asOfDate` once set) older than 90 days warns, and fails the strict release build. Consequences: the strict build breaks on 2027-01-19 unless the owner re-states the figures (OT-12); 90 days is the lead's call, the constant is `FIGURES_MAX_AGE_DAYS`.

**PD-E: The JavaScript budget is measured "on view".** Definition: gzip level 9, per page, static import closure of every script and island plus inline scripts, 81,920 bytes; dynamic imports (loaded after an interaction) reported separately and not counted. If the lead prefers a stricter "ever loaded" definition the lazy figure is already printed (about 10.5 KB on the form pages).

**PD-F: The secrets loader asks git, never compares paths.** Decision: tracked and ignored status come from `git ls-files` and `git check-ignore` run in the file's own folder, on the given and the real path; no answer from git means refusal.
