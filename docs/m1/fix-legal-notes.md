## 3. Proposed decisions (for the lead to record in `docs/DECISIONS.md`; ids prefixed "Legal-fix")

**Legal-fix P-L1. Legal wording is gated by feature switches.**
Context: finding C-11; a legal page that describes a feature that is not live is a false statement to the public and, for YouTube, a mismatch with the API terms.
Decision: wording for later features and unconfirmed practices lives in `futureWording` blocks next to each page and is rendered only when `features.<name>` in `src/content/legal/status.ts` is true. Only the lead flips a switch, with the feature (or with the owner's yes in chat). `cloudflareWebAnalytics` is derived from the build token. Tests prove the off state, each on state and that code and switch agree (`tests/legal/features.test.ts`, `reality.test.ts`). The checklist is `docs/legal/G1_REREAD_CHECKLIST.md`.
Consequences: when a feature ships, three things change in one commit: the code, the switch, and the "last updated" date; the lawyer re-reads the added wording.

**Legal-fix P-L2. Optional owner text hides, required owner text stays a Todo.**
Context: finding C-14 and D-034.
Decision: `LegalSection.showWhen` / `showWhenAny`, block-level `showWhen` and table `rowShowWhen` hide an item until a fact in `facts.ts` is supplied; `LegalDocument` leaves `<template data-owner-hidden="legal-<fact>">`. Todos remain only for: identity, contact and grievance officer, refund and delivery rules, court city, lawyer review.
Consequences: three fewer Todos at G1; the owner can ignore the three optional items and still launch.

**Legal-fix P-L3. Telegram phone link: default off, owner and lawyer decide (same as R-TELEGRAM-PHONE).**
Context: S-5, C-4, D-029 says alerts carry no contact. Decision needed from the owner (and the lawyer): may the alert carry a reply link that contains the customer's phone number? Recommended: no at G1; read the lead in Supabase Studio (M3 admin later). If yes: set `features.telegramPhoneLink` and the Worker variable `TELEGRAM_ALERT_PHONE_LINK=true` in one change, re-read the `lead-notice` consent text (it does not say the phone goes to Telegram; changing it needs a new version and a new pin), and record it in D-029.
Consequences: default policy text and code agree; a guard test fails if the default alert ever holds a phone.

**Legal-fix P-L4. Disclosures promise only the owner's recorded practice.**
Context: C-11 (ASCI duration rules shown as the owner's own practice). Decision: the page states spec 15.5 and links the ASCI guidelines; the label-length figures are not restated. The health and supplement rule is held back until the owner confirms it.

**Legal-fix P-L5. Security-log retention wording.**
Context: the old text ("for the period that Indian security rules require") described a practice that does not exist on free plans. Decision: "kept by our hosting and database providers for the period their service sets". Open for the lawyer: whether a CERT-In style 180-day log is needed (briefing 4F item 4).
