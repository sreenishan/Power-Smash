# Port B notes: headers, redirects, middleware, noindex (Vercel)

Area B is done in code and unit tests. Verified against `docs/m3/vercel-facts.md` and the Build Output API docs (vercel.com/docs/build-output-api/configuration, fetched 2026-10-22).

## Design
- Headers and redirects are written as `routes` into `.vercel/output/config.json` (Build Output API v3), NOT into vercel.json. Reason: the CSP holds hashes of the inline scripts and styles of the built pages, known only after the build, and `vercel build` reads vercel.json before building.
- A managed block sits first in `routes`, between two sentinel routes (`^/\.ps-managed-begin$` and `^/\.ps-managed-end$`, header `X-PS-Managed`). A second run replaces it (idempotent). The adapter's own routes follow untouched.
- Header routes use `continue: true` (headers only, they never answer). Redirect routes end routing with status 301 and a `Location` header. Every route counts towards Vercel's 2,048 per deployment; header rules use about 10; redirect release line stays 1,800 (D-009).
- Pure code: `src/lib/infra/vercel-routes.ts` (route builders, sentinels, limits, `parseHostSuffixes`) and `src/lib/infra/headers.ts` (CSP, base headers, noindex logic, unchanged guarantees). Script glue: `scripts/finalize-headers.ts`, `scripts/lib/headers-file.ts`.
- Rules: base headers on every path (nosniff, Referrer-Policy strict-origin-when-cross-origin, Permissions-Policy, X-Frame-Options DENY, HSTS only when PUBLIC_HSTS_MAX_AGE is valid, `X-Robots-Tag: noindex, nofollow` unless PUBLIC_ALLOW_INDEXING is exactly `true`); page CSP with hashes on every path except `/api`, `/go`, `/cdn-cgi`; those get the locked-down API CSP plus `Cache-Control: no-store`; `/_astro/*` gets `public, max-age=31536000, immutable`. Indexing on: noindex still on `/api /go /admin /cdn-cgi`, on every host ending `.vercel.app` or listed in `PUBLIC_NOINDEX_HOST_SUFFIXES` (comma list, `.vercel.app` always included), and on every host that is not the `PUBLIC_SITE_URL` host.
- CSP outside hosts: Turnstile (`challenges.cloudflare.com`, a Cloudflare service that works on any host), YouTube nocookie, Cloudflare Web Analytics only when `PUBLIC_CF_ANALYTICS_TOKEN` is set, Supabase origin when set.
- Header value size: Vercel documents no limit; we fail above 6,000 characters per value as a precaution (`HEADER_VALUE_SOFT_MAX`). The old Cloudflare 2,000-character and 100-rule limits no longer apply.
- Middleware (`src/middleware.ts`) still adds the same headers to function responses and never overwrites existing ones, so no conflict with the route rules. It now reads `PUBLIC_NOINDEX_HOST_SUFFIXES` too.
- Redirects: `src/lib/archive/redirects.ts` is unchanged in behaviour (pure, flattened, protected-name safe, 410 replaced by a 301 to the neutral noindex `/matches/gone/`). `scripts/write-archive-redirects.mjs` now writes `tmp/archive-redirects.json` (`[{from,to,status}]`); finalize turns each into a route `^/from/?$` (so the address without the slash redirects too).
- Trailing slash: nothing is set. Pages build to `dir/index.html`, internal links end with a slash, so `/book/` is served from the file directly and cannot loop. We deliberately do NOT set vercel.json `trailingSlash: true`, because it would also redirect `/api/lead` and `/go/x` (a POST would break). TO VERIFY on the first preview: `/book` (no slash) behaviour and `/api/lead` with and without a slash. Vercel docs do not state the default when unset.
