# CLAUDE.md - Power Smash

Guide for Claude Code sessions in this repo. The spec, the plan and the decision records are the source of truth; this is the short version.

## What this is
Power Smash is a YouTube-first Tamil Nadu badminton media brand (@PowerSmash, about 88K subscribers). This repo builds its website, admin console and automation: the **Archive** (player, match, tournament pages from the YouTube catalogue), the **Storefront** (priced, bookable services, sponsor slots) and the **Hub** (WhatsApp, alerts). Phase 1 = milestones M0-M4; M0 (setup, Windows 10 gate G0, parser fixtures, brand kit) is built: G0 passed on the owner's Windows 10 PC on 2026-10-21 (`docs/G0_RESULT.md`); the real CI deploy and Lighthouse are still pending (OT-02, the Vercel account and project, and the owner's approvals). **Hosting moved from Cloudflare Workers to Vercel on 2026-10-22 (D-097, owner decision; the live commercial site needs Vercel Pro, an owner purchase).** M2 and the unblocked M3 slice are built on fictional data (parser, archive pages, admin console, sync code, QR posters, video and alert forms); nothing talks to a real Supabase or YouTube yet. M1 (money pages, enquiry forms, Telegram alerts, legal drafts, release gates) is built and has had a three-way review and fix wave (`docs/m1/fix-*-notes.md`); nothing is public: the strict release build refuses while owner inputs are missing (OT-12, OT-19 to OT-22, OT-41), and the deploy workflow (Vercel, prebuilt upload) is off until `DEPLOY_ENABLED` and the owner's Vercel project exist. The owner is a non-developer who works from a phone: every routine task must be possible from the admin, and owner-facing text is plain English.

## Commands (the project path contains a space: always quote it)
- `npm ci` install exactly the lockfile (install scripts are off). Only the lead/G0 changes dependencies.
- `npm run dev` Astro dev server. `npm run preview` serve the build. `npm run test:watch`.
- **`npm run build` = the NON-STRICT developer build** (`scripts/build.mjs`: `astro build`, then `scripts/write-archive-redirects.mjs` (writes `tmp/archive-redirects.json`; Vercel redirects cannot return 410 either, so removed and protected-old addresses 301 to `/matches/gone/`), then `finalize-headers`, which writes the CSP, noindex, HSTS and redirect rules as routes into `.vercel/output/config.json`; the adapter writes the build to `.vercel/output`, static files in `.vercel/output/static`). It only reports placeholders and private data, never blocks, and says so on its first and last line. Never call `astro build` directly (the header and redirect step would be skipped; `.npmrc` `ignore-scripts=true` also stops npm `postbuild` hooks).
- **`npm run build:strict` = the release gate** (`PS_STRICT=1`, `scripts/build-strict.mjs`): release variables, build, headers, placeholder gate (any `TODO(owner)` fails), privacy scan, release check, JS budget. It needs the six `PUBLIC_*` variables and currently fails on purpose (about 128 owner-input markers on 18 pages). It is the ONLY build `deploy.yml` runs (D-008, review C-5).
- Gates you can run alone against the build output (`.vercel/output`): `npm run check:placeholders` (lists hidden `data-owner-hidden` sections too), `check:privacy`, `check:release`, `check:js-budget` (first-party JS on view, gzip, 81,920 bytes per page; also in CI and step 7 of `build:strict`).
- `npm run check` = `astro check` (types, must be 0 errors; it reads everything under the project root except `dist` and `tmp`, so keep scratch builds in the system temp folder).
- `npm test` = `vitest run`: all GREEN (about 2,500 pass at M2b, more since, a few skipped). The parser (M2b, `src/lib/parser/`) is implemented and the former RED files are ordinary tests now (`tests/parser/gold-scorecard.test.ts` reports agreement with the 70 gold titles; labels stay `proposed` until the owner spot-checks, OT-35). `vitest.red.config.ts` and `npm run test:red` are leftovers the lead may delete. Do not weaken a fixture to make it pass.
- **`npm run e2e`** = Playwright (Chromium only, phone sizes 360 and 390 wide, axe checks, stubbed Turnstile and `/api/lead`). It needs a fresh build (`.vercel/output`) and starts and stops `scripts/serve-output.mjs` (also `npm run preview`; `astro preview` does not work with the Vercel adapter) on port 4399 itself; run it under the heavy lock after `npm run build`. Never leave a server running.
- **Local PostgreSQL 17 (portable, `tools/pg/`, git-ignored): `node scripts/pg-local.mjs <start|stop|apply|check|status|reset|all>`** (also `npm run pg:local --`). Port 54329, trust auth, fictional data only. **One PostgreSQL user at a time: always `stop` it when done** (a second session must not find it running). `apply` = `supabase/local/roles.sql` plus every migration; `check` runs `supabase/checks/*.sql`; `tests/supabase/local-pg.test.mjs` skips unless the server is up.
- The build-output tests (`tests/build/*`: hidden-section markers, every internal link resolves, owner-section names) read the build output (`.vercel/output/static`) and SKIP without it. Build first, then `PS_REQUIRE_DIST=1 npx vitest run tests/build` (the variable turns a missing build output into a failure; CI does this after the build).
- **Heavy commands share one lock** (2-core, 8 GB dev PC; several sessions may run): `node scripts/with-lock.mjs heavy -- npm run build` (same for `npm run check`, `build:strict`, any Playwright or measuring run). One at a time; waits up to 40 minutes; a lock older than 30 minutes is stale (`tmp/locks/`, git-ignored). The build output folder is shared: inspect it straight after your own build. Never leave a server running.
- Owner-run helpers (Claude never runs them with real values): `npm run secrets:load -- --dry-run` (the loader; `--only vercel|github`), `npm run telegram:chat-id`, `npm run age:keys`. See `docs/SECRETS.md`.
- CI runs: gitleaks, `npm ci`, `check`, `test`, `build`, the three non-strict gates, `check:js-budget`, then `PS_REQUIRE_DIST=1 npx vitest run tests/build` (not `test:red`). Production deploys come only from `.github/workflows/deploy.yml` (strict build on a GitHub runner, then `vercel deploy --prebuilt --prod`; `main` only; off until `DEPLOY_ENABLED`; needs the `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` secrets and Vercel's own Git deploys disconnected), never from a laptop and never from Vercel's Git integration (D-008, D-097). `.github/workflows/preview.yml` makes a private non-strict preview (off until `PREVIEW_ENABLED`; no `--prod`). No wrangler, no `wrangler.jsonc`: `vercel pull` is not used in CI because it would copy production secrets into the build job.

## Conventions
- TypeScript strict. Node 24 (`.nvmrc`; engines `>=22.22.0`). npm only, exact pins, committed lockfile.
- `.npmrc` policy (D-002): `ignore-scripts=true`, `min-release-age=7`, `save-exact=true`, `engine-strict=true`. A package that needs a build step gets an explicit `npm rebuild <pkg>` and a note in DECISIONS, never a blanket re-enable.
- **Never run a bare `npm install typescript`.** TypeScript is pinned to 6.0.x; TypeScript 7 breaks `astro check`. Dependabot ignores TypeScript major 7.
- Windows-safe: scripts are Node `.mjs`/`.ts` files, no POSIX-only shell in npm scripts (use `cross-env` if needed). Line endings LF (`.gitattributes`, `.editorconfig`).
- Money is stored as **integer paise**. No price, fee, tax rate or discount is hardcoded or defaulted anywhere (they are settings and per-payment records, D-020/D-021).
- Dates: store instants as `timestamptz` (UTC) and event dates as `date` read as Asia/Kolkata; format only through one `lib/dates.ts` with `Intl.DateTimeFormat('en-IN', {timeZone: 'Asia/Kolkata'})`; `TZ=Asia/Kolkata` in CI (D-030).
- Store the raw YouTube title byte-exact for display plus a normalised copy for matching; key everything on the video ID, never the title (D-017). One parser module, shared by tests, admin Title check and sync.
- No `dangerouslySetInnerHTML` or `set:html` (the one exception is `src/components/ui/JsonLd.astro`, fed only by `safeJsonLd()`); JSON-LD through the safe serialiser.
- **WhatsApp:** links only through `waLink()` / `waShareLink()` and numbers only through `normaliseWhatsAppNumber()` in `src/lib/whatsapp.ts` (D-029, D-025); never write a `wa.me` URL by hand. The number is the `PUBLIC_WHATSAPP_NUMBER` build variable; no number = the button is hidden.
- **Internal links end with a slash** (`/book/`, because pages build to `book/index.html`), always written through `src/lib/urls.ts`: `path()`, `absoluteUrl()` and `ROUTES` (nav, breadcrumbs, canonical, `og:url`, JSON-LD). Endpoints (`/api/*`, `/go/*`, `/cdn-cgi/*`) and files keep no slash and never go through it. `tests/build/links.test.ts` checks the built output.
- **Owner input (D-034):** `<OwnerSection when={value} name="kebab-case-name">` hides optional content and leaves `<template data-owner-hidden="name">`; the name is required, unique per call site, at most 40 characters (`src/components/site/owner-section.ts`; a test scans for it). `<Todo what="...">` marks required input and is the ONLY way `TODO(owner)` appears in a page; never type it by hand into a public page. Product enquiry links come from `enquiryHref()` in `src/content/products.ts` (coverage `/book/?package=`, sponsor `/partner/?package=`, everything else `/contact/?topic=<key>`); the form only pre-fills from a key on its allow-list, never from free text in the URL.
- **Forms and lead endpoint:** the client and the server function share one rule module, `src/lib/contracts/lead-constants.ts` (phone clean-up, allowed characters, start-date window, `elapsedMs` clamp); a change there is a change on both sides, and `tests/forms/parity.test.ts` must stay green. Server settings (Vercel environment variables, read from `process.env`) are read only through `src/lib/runtime-env.ts` (never from a page); the client IP comes only from `src/lib/security/client-ip.ts` (Vercel's `x-vercel-forwarded-for` first; `cf-connecting-ip` is ignored); every switch is off unless it is exactly `true` (`docs/SECRETS.md`).
- **Tests use fictional data:** fake phone numbers (for example `910000000000`), fake emails and invented names; never the real WhatsApp number, the owner's Gmail or a real player. Build secret-shaped fake values at run time (`['sb', 'secret', 'FAKE'].join('_')`) so the gitleaks rules do not flag the test files. Inject a clock into anything date-dependent. Scratch files named `tests/zz_*` are git-ignored: delete them before the first commit.
- **Legal pages say only what is true today:** wording for a later feature or an unconfirmed practice lives in a `futureWording` block behind a switch in `src/content/legal/status.ts` and is re-read against `docs/legal/G1_REREAD_CHECKLIST.md` before G1.
- **Archive and protected players (D-012, `src/lib/archive/`):** one place decides (`protected.ts`, fail closed): an unknown or unrecognised age is protected. Only `adult_confirmed` players with a full match get a profile; unknown age gets a minimal noindex page (opaque slug, NO name, removal link only, while `unknown_match_mode = noindex_minimal`); minors get nothing. Matches are `full | listed | minimal | hidden` (`model.ts` drops hidden ones). Non-TN or undetectable-place events are `listed_no_player_pages`. The raw title is the only place a protected name can appear. Data comes through the `ArchiveProvider` interface: a FICTIONAL seed by default, the Supabase REST provider (publishable key, `api` views) only when `PS_ARCHIVE_SOURCE=supabase`; strict builds refuse the seed (`ArchiveSeedNotice`). Page budget guard in `budget.ts`.
- **Admin (`src/lib/admin/`, `src/admin/`):** everything goes through the `AdminStore` interface (`memory-store.ts` fictional seed for tests and preview, `supabase-store.ts` for real). POST `/api/admin/<action>` needs a `jose`-verified token, `aal2`, the role from `profiles`; editors are off. The admin shell is noindex, unlinked, tokens in memory only. Real sign-in needs the owner steps in OT-51.
- **Feature flags live in `src/content/legal/status.ts`** (`youtubeApiData`, `youtubeEmbeds`, `archivePages`, ...), all false until the owner and lawyer approve; `tests/legal/reality.test.ts` fails if a non-parked file uses `lib/sync` while `youtubeApiData` is false.
- **Sync is parked:** `sync.yml` (a GitHub schedule every 6 hours) runs only when the variable `SYNC_ENABLED` is exactly `true`. The Cloudflare Worker `scheduled()` entry is deleted; `scripts/sync-worker/vercel-cron.ts` (a GET route guarded by `CRON_SECRET`) is parked outside `src`, `vercel.json` has no `crons`, and `CRON_ENABLED` likewise. Activation needs the owner's yes, Vercel Pro for sub-daily crons and the YouTube-API legal switch (see `docs/m3/vercel-deploy-notes.md`, `docs/m2/wiring-notes.md`).
- Tailwind 4 through `@tailwindcss/vite`, tokens in a CSS `@theme` block. Fonts self-hosted via Fontsource (Noto Sans Tamil in the heading stack). Icons via `@lucide/astro`.

## Architecture summary (D-001 to D-011)
- **Hosting (D-097, supersedes D-001):** Vercel: Astro 7 + `@astrojs/vercel` (static output; `prerender = false` routes become Node functions, region `bom1`), Pro plan for the live site (Hobby is non-commercial only; the owner buys Pro). Headers, CSP hashes and archive redirects are routes in `.vercel/output/config.json` written by `finalize-headers` (not `_headers`, `_redirects` or `vercel.json`); no `trailingSlash` setting. Deploy = strict build on GitHub then `vercel deploy --prebuilt --prod`. Turnstile, Web Analytics and Email Routing stay on Cloudflare. Prerender every public content page; `prerender = false` only for `/go/*`, form endpoints, the beacon, `/api/*`, live status, webhooks and privileged admin actions. No Astro sessions/KV. The site never renders card or UPI-credential fields.
- **Toolchain (D-002/D-003):** pins in `package.json`; G0 Windows 10 smoke test with a fallback ladder (node prerender, then Linux CI builds, then owner-approved WSL2/Windows 11).
- **Data (D-004/D-005):** two Free Supabase projects in Mumbai (`powersmash-prod`, `powersmash-dev`), no Docker. Public data leaves the database only through explicit-column views in the `api` schema (no `select *`, masking in SQL). Every migration enables RLS, adds policies and explicit GRANTs. The static build reads with the **publishable** key; the build job never holds the secret key. Every list read is paginated (1,000-row cap). Anon-access tests run in CI against the live REST API.
- **Auth/admin (D-006/D-007):** sign-ups disabled; role only from `profiles.role` via a SECURITY DEFINER function; Vercel functions verify JWTs with `jose` and require `aal2`; owner-only admin SPA on its own hostname; privileged actions are SECURITY DEFINER RPCs that audit.
- **Freshness (D-008):** dirty flag + `workflow_dispatch` (the parked Vercel cron route would call it; Hobby cron is once a day at most); nightly deploy 00:30 IST (commented out until deploys are live); sync every 6 hours (GitHub schedule); deploys serialised by `concurrency: deploy` with no cancel; the deploy trigger is `workflow_dispatch` only (token = Actions: write on this one repo, OT-42). Vercel cron is a GET with `Authorization: Bearer <CRON_SECRET>`, best effort, no retries (VF-V4). **Budgets (D-009, amended by D-097):** warn at 10,000 / fail above 14,000 output files as a soft guard (Vercel has no output-file cap; the 45-minute build time is the limit, VF-V1/V8); header, redirect and rewrite rules together stay under 2,048 routes (redirects capped at 1,800, VF-V5); posters and creatives live in Storage, never in the build output. G0 measured about 1.0007 files per prerendered page on the old host, so the file budget is still effectively a page budget. Function body cap 4.5 MB (VF-V8). **Search (D-010):** one JSON index of public `adult_confirmed` players and tournaments; protected players never indexed. **Backups (D-011):** weekly encrypted `pg_dump` via the session pooler; the `age` private key stays offline with the owner.

## Privacy rules
- **Protected players (D-012):** everyone whose `age_status` is not `adult_confirmed` (unknown included) is protected: no profile page, noindex, absent from sitemaps/search/JSON/other pages, no sponsor slot, beacon, Follow or share text naming them. Enforce in the `api` view SQL and the layout flag, with tests. Never lift a flag from a self-claim.
- Private fields (organizer contacts, leads, phone, email, `tournament_private`, `sponsor_contacts`) never reach the public build or static HTML (D-005, D-029); the privacy scan fails the build on a hit (it reads decoded text, so entity or escape tricks do not hide a number).
- **Owner alerts carry no contact data by default:** Telegram and the owner email hold only the kind, reference, first name or initial, source page and a pointer to the lead in Supabase Studio. The customer's phone (inside the `wa.me` reply link) appears only when `TELEGRAM_ALERT_PHONE_LINK` is exactly `true`, which needs the owner's yes AND the lawyer's updated privacy text (`features.telegramPhoneLink`). A test fails if the default alert ever holds a phone, link or email. The customer acknowledgement promises a reply time only when the owner sets `site.replyTimePromise`; never write a default such as "24 hours".
- **Turnstile test keys never reach production:** Cloudflare's published test secrets are accepted only when `TURNSTILE_ALLOW_TEST_KEYS` is exactly `true` (Vercel Preview scope and local only); otherwise `/api/lead` fails closed (`degraded`) and `/api/health` reports `ready:false`. The uptime keyword is the exact text `"lead":"ready"`, never the bare word `ready`.
- **Real titles and real players' names live only in `tests/fixtures/` of this PRIVATE repo.** Never in seed data, previews, screenshots, docs outside `tests/`, issue text, or any web service. Dev and preview use fictional data only; never the real WhatsApp number or the owner's personal Gmail in dev data (D-004).
- **Secrets (D-027, `docs/SECRETS.md`):** names only in the repo; values never in files, chat or logs. **Claude never types, pastes, reads or pipes a secret value** into any field, command or file, even when offered. The owner enters each secret directly in the vendor's web screen (phone) or runs the loader at the PC; Claude only writes the loader script and the checklist and never runs it with real values, never opens `.secrets.local` or a local `.env` holding real values, and never asks for output that could contain a value. If a value is pasted into chat, say so and start rotation. Non-secret values (project ref, Vercel org and project ids, publishable and site keys, `age` public keys) are fine. Variable names: `AGE_PUBLIC_KEY` and `AGE_DRILL_PUBLIC_KEY` (public repository variables), `AGE_DRILL_KEY` (secret), `REBUILD_DISPATCH_TOKEN` (Vercel secret), `CRON_SECRET` (Vercel secret), `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` (GitHub secrets). Never read `.vercel/` project files or paste a Vercel token. Never put the secret key in the build job or any `PUBLIC_` variable.
- **No GitHub secret scanning here:** secret scanning alerts and push protection are not available on private repositories on the Free plan (verified 2026-10-21). Protection is gitleaks in CI (no licence key needed on a personal account) plus an optional local pre-commit hook (the gitleaks binary needs the owner's yes), `.gitignore` and the `dist/` scan. **Never make the repo public to get scanning.**
- YouTube rules (D-016): show the raw title unmodified, label parsed data "by Power Smash", no composite or view-based scores, stored API data refreshed or deleted before day 30 (hiding it is not enough, policy III.E.4.d), sponsor slots only beside the player and only on pages with real independent content.

## Never fabricate
Statistics come from the YouTube API or the owner. Testimonials, sponsor names and logos, prices, addresses, audience figures, versions and URLs come only from the owner or a verified source; otherwise write `unknown` or `TODO(owner)`. `TODO(owner)` is allowed in docs and drafts but **never on a public page** (nor in admin defaults by the end of M3): `scripts/check-placeholders.ts` fails the strict release build (`npm run build:strict`) on it, and sections waiting for an owner input hide automatically (D-034).
