# Changelog

All notable changes to Power Smash are recorded here, newest first. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/). The project has no public release yet, so version numbers (which would follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html)) start at the first public go-live (gate G1 in `docs/BUILD_PLAN_PHASE1.md`).

Update this file in every vertical slice (spec section 0 rule 11). Write for the owner: say what changed for them, not which file moved.

### Changed

*Hosting moved from Cloudflare Workers to Vercel, 2026-10-22 (owner decision, D-097); nothing was ever deployed on Cloudflare, so nothing is migrated*

- **The website will be hosted on Vercel.** The plan, decision records and owner steps are rewritten (OT-02 is now the Vercel account and project, not a Cloudflare deploy key). The live site needs Vercel's Pro plan, USD 20 a month per seat, because the free Hobby plan is for non-commercial use only and this site advertises paid services and sponsor slots; you buy it yourself shortly before launch and I never enter a card. The free Hobby plan is enough for the private preview.
- **What stays on Cloudflare:** the spam check on forms (Turnstile), the optional page counter (Web Analytics) and email forwarding for hello@ (Email Routing). What is gone: the Worker, workers.dev addresses, the Cloudflare deploy key, the 20,000-file cap and the Cloudflare rate-limit binding.
- **Docs.** New decision D-097 (hosting), with one-line "Amended by" or "Superseded by" notes on the older decisions it changes (D-001 is superseded); Vercel facts added to VERIFIED_FACTS as VF-V1 to VF-V8, with the research in docs/m3/; the build plan, risk register (R-42 to R-45), runbook (deploy, roll back, change a setting on Vercel), owner guide, secrets list and README updated. New docs/PREVIEW.md: how to open the private preview on your phone behind a Vercel login.
- **The port is built, not just planned (2026-10-22).** The build now produces Vercel's output folder (`.vercel/output`) instead of Cloudflare's `dist`; the headers, redirects, release checks, JavaScript budget and the browser tests all read it. All 168 browser tests pass against it, the type check has 0 errors, and the strict release build refuses only because owner inputs are still missing (the placeholder gate), while its privacy scan, release check and JavaScript budget pass. Small fixes on the way: the admin preview's pretend data no longer contains an email-shaped value (the privacy scan rejects those), `npm run preview` serves the new output folder, and `npm run profile` runs the catalogue profiler. The YouTube sync runner gained a read-only rehearsal (`backfill --dry-run`: real YouTube reads, nothing written anywhere, counts only, including how many match videos the parser accepts) for connect day. The bundler `esbuild` is now pinned in the project instead of being downloaded unpinned each time it is needed (D-095). `npm audit` shows 3 high findings, all in the Vercel adapter's build-time routing helper; they are explained in D-097 and not fixable without an older adapter.
- **Independent security review of the port (2026-10-22): no critical or high findings; 12 smaller ones: 9 fixed and 3 recorded for the first preview or before launch.** Fixed: the privacy page said Cloudflare hosts the site (it now names Vercel, and Cloudflare only for the spam check and the optional page counter; your lawyer re-reads that table before G1); sponsor links, the click log and the admin screen silently stopped working if only the build-time database address was set; the owner alert on a new enquiry could be lost when the platform gave no "finish after reply" hook (the visitor now waits for it instead); the sponsor-schedule address could be made to hit the database on every request by adding a random `?x=`; an image endpoint the site never uses is now switched off (and the function is 20 MB smaller); Vercel's own Git deploys are switched off in `vercel.json` (you still disconnect Git in Vercel, OT-02) so an unchecked build can never go live that way; the Vercel command-line tool used for deploys now comes from its own lockfile instead of being downloaded live (the secrets loader refuses to run without that locked copy: `npm run vercel:install` once); the loader stores every Vercel value as write-only (so keep your own copy of each value); the workflows that hold production credentials now run only from `main`, with a test that fails if a new one forgets. Recorded, not built: `/api/event` has the weakest flood protection (a Vercel firewall rule or a daily cap is needed before launch, risk R-45); the host-based noindex rules are valid in Vercel's own format but untried; and Vercel's docs say it overwrites a visitor's forwarded address, so the visitor-address header was left as it is. To prove on the first preview: the noindex rules, that a faked visitor address is ignored, the function region, and that the locked CLI runs.
- **The code is on GitHub and the Vercel project exists (2026-10-22 and 2026-10-23).** The private repository holds the whole tree in 7 commits; the CI run starts on every push and the deploy job stays skipped until you switch it on. The empty Vercel project `power-smash` now exists in your Hobby account, made from the command line because the dashboard's import button can only create a project by also publishing a first build (the checklist step "import but do not deploy" was wrong and is corrected in OT-02). It has no repository connected and nothing built. Vercel Authentication is on by default, Node is 24.x, and, with your yes, the function region is now Mumbai (it takes effect on the first deployment). The two Vercel identifier secrets (`VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`) are stored on GitHub; the deploy token `VERCEL_TOKEN` is still yours to add. The locked Vercel tool runs fine under our install-scripts-off policy.
- **First private preview ran (2026-10-23), and it was briefly public by mistake.** The Preview job built and uploaded the site (proving the Vercel upload, the header rules, the Mumbai region and the health endpoint), but Vercel made that first upload the project's production deployment, and the standard login protection leaves the production address public, so `power-smash-nu.vercel.app` opened without a login for about six minutes (10:17 to 10:23 UTC). It held only the made-up sample site (noindex, nothing connected). With your yes I set the protection to **All Deployments** (every address now asks for a Vercel login, checked from outside), and the Preview job now asks for a preview explicitly and refuses to upload if the protection is not on. At launch the protection must be relaxed so the public can see the live site (it is on the G1 list).
- **Unverified, to prove on the first preview:** the prebuilt deploy with the Vercel command-line tool under our install-script policy, Vercel's behaviour for a page address without the trailing slash, the Instant Rollback and Promote buttons, connecting the .in domain, and whether Cloudflare's page counter accepts a vercel.app address.

From the three independent M1 reviews (security 17 findings, correctness 18, conformance 23); the full list, with the file where each fix lives, is `docs/SPEC_AUDIT.md` section 9.

- **Phone numbers pasted with invisible characters** (no-break spaces, direction marks) are accepted, and text boxes accept the rupee sign, en and em dashes, curly quotes, `%`, `!`, `?` and the middle dot. A start date must be real, from yesterday to three years ahead.
- **A form left open for over 24 hours** can be sent; **a `null` request body** gives a plain 400 instead of a server error; **a "temporarily unavailable" answer** no longer re-sends a spent spam-check token; **failed attempts** no longer lock a visitor out for an hour.
- **Pressing Send before the form loaded** can no longer reload the page; the form is disabled until it has loaded and a no-script message points to WhatsApp.
- **Product enquiry links** keep the product: coverage packages go to `/book/?package=<key>`, sponsor packages to `/partner/?package=<key>`, everything else to `/contact/?topic=<key>`, and the form only fills the message from a known key.
- **A `/go` link could redirect to `//evil.com`**; a protocol-relative path is now refused after normalisation. The click log accepts only a real id and ignores repeat clicks and floods.
- **A mistyped WhatsApp number** (10 digits without 91, or a leading 0) is refused by the link helper and the release check instead of publishing dead links on every page.
